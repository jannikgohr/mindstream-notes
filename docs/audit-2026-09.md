# Codebase audit — September 2026

Full-tree audit of `mindstream-notes` at `v0.1.15`, run over three passes on
2026-09-04 and consolidated 2026-09-07. Roughly 160k lines of source (125k
frontend, 34k Rust), 1,014 tracked files, one author.

This document is a working checklist. Findings carry a stable id (`C1`, `H5`, …)
so they can be referenced from branches and commit messages. Tick the box when a
finding is fixed **and** covered by a test.

## Method

Read-and-trace rather than pattern-matching: transaction boundaries, the sync
push/pull cycle, the sharing permission model, the collab wire protocol, both
plugin sandboxes, migration history, Tauri's security config, and async
lifecycles in the editors. Everything below was confirmed by reading the code
path, not inferred from a grep hit.

## Critical

### C1 — `shared_role` is stored, displayed, and never enforced

- [x] Fixed and tested

**Evidence.** All 23 non-test references to `shared_role` are a struct field, a
`SELECT`, an `UPDATE` that sets it, a migration, or serialization to the
frontend. There is no comparison of it anywhere in the Rust tree.
`notes::update` (`src-tauri/src/notes/mod.rs:456`) goes straight from signature
to `conn.transaction()` to `UPDATE notes SET …`. Same for `trash`, `restore`,
`purge`, and `tree_batch::move_many_items`.

**Impact.** Read-only sharing is a UI convention. A read-only recipient's client
accepts `update_note`, writes it locally, sets `dirty = 1`, and `push_notes`
attempts the upload. Etebase's server ACL is the only real backstop, so the
failure mode is a local DB diverged from the server plus a sync loop that either
wedges on a permission error or drops the edit with no user-facing signal.

**Note.** The two tests named in `docs/security-review.md` (read-only member
cannot write; revoked member loses access) are not missing by oversight — there
is no code for them to test. This is design work, not a patch.

### C2 — Push clears the dirty flag across a network round trip

- [x] Fixed and tested

**Evidence.** `src-tauri/src/sync/push.rs:89-190`:

```rust
let dirty = load_dirty_notes(db, scope)?;   // snapshot
for row in &dirty { im.fetch(uid, None)?; } // network, per note
transact_or_resolve(...)?;                  // network
// then, unconditionally:
tx.execute("UPDATE notes SET … dirty = 0 WHERE id = ?5", …)
```

No `AND modified = ?` and no etag guard. The DB mutex is held only for the final
transaction, not across the fetches, so `notes::update` interleaves freely. The
only sync lock (`in_flight: Mutex<()>`, `src-tauri/src/sync/scheduler.rs:54`)
serialises sync against sync, never sync against the editor.

**Impact.** Autosave writes every 800 ms while typing; sync runs on a scheduler.
Typing during a sync is the normal case. Any keystroke landing in that window is
marked clean without being uploaded. It does not self-heal: on the next pull
`src-tauri/src/sync/apply/notes.rs:128` returns `(merged, local.dirty)`, so the
CRDT merge preserves the edit locally with `dirty` still `0`. The note is correct
on this device and stale on every other one, permanently.

**Fix.** `WHERE id = ?5 AND modified = ?6`, binding the snapshotted `modified`.
Rows that changed mid-flight keep `dirty = 1` and go out next cycle.

### C3 — Trash has two sources of truth that disagree

- [x] Fixed and tested

**Evidence.** Two independent representations: the `trashed_at` column, and the
`parent_collection_id` chain terminating at `TRASH_ID`. `tree_batch.rs:169`
(`move_folder`) stamps `trashed_at` on the folder only — notes inside keep
`trashed_at = NULL`.

| Consumer                               | Predicate            | Note inside a trashed folder |
| -------------------------------------- | -------------------- | ---------------------------- |
| `search()` (`search/mod.rs:62`)        | `trashed_at IS NULL` | **still returned**           |
| `pdf_text` indexing (`pdf_text.rs:40`) | `trashed_at IS NULL` | still extracts text          |
| `notes::list` (`notes/mod.rs:299`)     | `trashed_at IS NULL` | returned (tree hides it)     |
| retention sweep (`data.rs:312`)        | recursive descent    | correct                      |
| frontend `isTrashed`                   | parent chain         | correctly hidden             |

**Impact.** Trash a folder, search for a note inside it, get a hit, click it,
land in a note the file tree shows as deleted.

**Origin.** Migration 11 (`db/migrations.rs:296`) backfilled only rows whose
_direct_ parent is `'trash'`. `trashed_at` was added for retention; the parent
chain was the original model; they were never reconciled.

**Caveat.** The existing test `trashed_notes_excluded` (`search/mod.rs:434`)
calls `notes::trash(id)` directly — the one path that does stamp the column. It
passes and proves nothing about the folder case.

### C4 — Merging a backup silently re-parents existing root folders

- [x] Fixed and tested

**Evidence.** `src-tauri/src/backup/merge.rs:88-114`. Pass 1 inserts backup
folders with `parent = NULL`, skipping ids already present:

```rust
if exists.is_some() { continue; }   // pre-existing folder: not inserted
```

Pass 2 identifies "folders we just added" like this:

```rust
// Only re-parent folders we just added (don't touch pre-existing
// ones whose parent might be intentionally different locally).
let was_added: Option<i64> = tx.query_row(
    "SELECT 1 FROM collections WHERE id = ?1 AND parent_collection_id IS NULL", …
```

`parent_collection_id IS NULL` is not "we just added it" — it is also every
folder the user keeps at the root of their vault.

**Impact.** User has a root-level folder `Projects`. The backup has a folder with
the same id nested under `Archive/2024`. Pass 1 skips it; pass 2's check passes
anyway; `Projects` and all its notes move under `Archive/2024`. The comment
directly above the check states the behaviour the code fails to implement. This
runs on an explicit, user-initiated merge — the operation with the lowest
tolerance for surprise.

**Fix.** Collect inserted ids into a `HashSet<String>` in pass 1; test membership
in pass 2.

### C5 — The plugin preview proxy is unauthenticated and launders `Origin`

- [x] Fixed and tested

**Evidence.** `src-tauri/src/plugins/preview_service.rs:377`:

```rust
fn handle_proxy_connection(mut client: TcpStream, data_port: u16, …) {
    let Ok(request) = read_http_head(&mut client) else { return };
    if request.is_empty() { return; }
    if is_websocket_upgrade(&request) { tunnel_websocket(…) }
    else { serve_proxied_html(…) }
}
```

No token, no `Origin` check, no `Sec-WebSocket-Key` validation
(`is_websocket_upgrade` is a substring match). Then `rewrite_ws_handshake:455`:

```rust
} else if lower.starts_with("origin:") {
    out.push_str("Origin: ");
    out.push_str(&upstream_origin);   // http://127.0.0.1:{data_port}
}
```

The client's `Origin` is **overwritten with a synthetic same-origin value**
before forwarding, defeating any origin check the upstream performs.

**Impact.** WebSocket connections are not subject to CORS. Any web page the user
has open in a normal browser can `new WebSocket('ws://127.0.0.1:PORT')`; the
handshake is accepted, `Origin` is rewritten to look local, and the page gets a
live tunnel to the Typst preview service rendering the user's note content.
Binding to `Ipv4Addr::LOCALHOST` prevents remote access, but localhost is
reachable from every browser tab on the machine, and the ephemeral port is
scannable.

**Fix.** A random per-session token in the URL path, checked in
`handle_proxy_connection`; pass the real `Origin` through (or reject non-empty
ones) rather than rewriting it.

## High

### H1 — Four `setupCollabProvider` copies leak live WebSockets

- [x] Fixed and tested

Every copy (`NoteEditor`, `KanbanNoteEditor`, `PdfNoteViewer`,
`InkWebNoteEditor`) has this shape:

```js
provider?.destroy();
provider = null;
const signingMaterial = await getOrCreateCollabSigningMaterial();
const room = await noteRoomInfo(noteId, …);   // two awaits
provider = new CollabProvider({
  …,
  onAuthStale: () => { void setupCollabProvider(); }
});
```

No `destroyed` flag or generation token after the awaits. Two failure modes:

1. **Unmount during connect.** `onDestroy` fires while `provider` is still
   `null`, destroying nothing. The await resolves and constructs a live
   WebSocket on a dead component, never cleaned up.
2. **Re-entrancy.** `onAuthStale` calls back into the same function. Two
   concurrent invocations both pass the null-out and both construct; the first is
   overwritten and orphaned — still connected, still applying remote updates into
   the same `Y.Doc`.

`src/lib/components/NoteKindRenderer.svelte` implements the correct pattern
(`loadToken` plus a `destroyed` flag checked after every await). It was never
propagated to the four copies. Fix alongside M1.

### H2 — `no-floating-promises` excludes every `.svelte` file

- [x] Fixed and tested

`eslint.config.js:131` scopes the type-aware rules to `src/**/*.ts` and ignores
`**/*.svelte.ts`. All 145 `.svelte` files and every rune module are exempt —
that is where nearly all async UI work lives. The stated reason
(svelte-eslint-parser cannot forward the TS program) is accurate; the outcome is
that the rule guards the layer least likely to have the problem.

Within the covered layer, compliance was reached by annotation: **285
`void`-prefixed calls with no `.catch` on the statement**, and there is still no
`unhandledrejection` handler. `void` silences the linter; it does not handle the
error. 236 `console.*` calls never reach the Rust log file.

### H3 — `notes::purge` tombstones outside a transaction

- [x] Fixed and tested

`src-tauri/src/notes/mod.rs:622`, with the reasoning inline:

```rust
// We do tombstone-then-delete on a plain &Connection (no transaction):
// tombstones is INSERT OR IGNORE and a stray tombstone for a
// never-deleted row is harmless.
```

A stray tombstone is not harmless — it instructs the next sync to delete the
item from the server. If the subsequent `DELETE FROM notes` fails (FK violation,
disk error, `n == 0` early return), the server copy dies, every other device
drops the note, and this device keeps it.

`purge_many_items` (`tree_batch.rs:60`) already wraps `notes::purge` in a
transaction, so the batch path is safe and the single-note path is not. Take a
`&Transaction`.

### H4 — Search scans all content under the global DB mutex

- [x] Fixed and tested

`src-tauri/src/search/mod.rs:58` selects every `body` and `pdf_text` with no
`WHERE` beyond `trashed_at IS NULL`, no `LIMIT`, and no FTS5. Then a per-note
`note_tags` query (N+1, defended by a comment — the same rationalisation removed
from `notes::list` in `perf/notes-list-tag-fanout`), then three `Vec<char>`
allocations per note including the full body _before_ testing for a match, then
a naive O(n·m) `contains_subslice`.

All under the single global SQLite mutex, fired every 100 ms while typing
(`src/lib/search/SearchDialog.svelte:37`). Autosave is 800 ms, so search takes
the write lock eight times more often than saves do.

**Fix.** FTS5 virtual table. Biggest single user-visible win in the codebase.

### H5 — `loadTree()` is a torn read across two transactions

- [x] Fixed and tested

`src/lib/api/tree.ts:38`:

```ts
const [collections, notes] = await Promise.all([
  listCollections(),
  listNotes(true)
]);
return composeTree(collections, notes);
```

Two Tauri commands, two DB transactions, no snapshot, while the sync scheduler
mutates concurrently. `composeTree` (`tree.ts:97`) handles inconsistency by
orphaning: a note whose `parent_collection_id` is not in `folderById` is pushed
onto `roots`. A folder created or deleted between the two calls makes its notes
visibly jump to the top level of the file tree until the next reload.

**Fix.** One `load_tree` Tauri command doing both reads inside a single
`with_conn`.

### H6 — The in-flight coalescer returns a stale promise post-mutation

- [x] Fixed and tested

`src/lib/stores/tree.svelte.ts:51`:

```ts
export function loadTree(): Promise<void> {
  if (inFlight) return inFlight;
  …
}
```

Correct for the startup double-fetch it was written for; wrong for the 33 call
sites shaped `await api.mutate(); await loadTree();`. If a load was already in
flight when the mutation committed, the caller joins a fetch that started before
the write, resolves with pre-mutation data, and proceeds believing the tree is
current.

**Fix.** A `pendingReload` flag set when `loadTree()` is called during a flight,
chaining a second fetch instead of returning the stale one.

### H7 — CSP `connect-src` allows the entire internet

- [x] Fixed and tested

`src-tauri/tauri.conf.json`:

```
connect-src 'self' data: blob: https: http: ws: wss: ipc: …
frame-src 'self' http://127.0.0.1:* http://localhost:* …
```

`https: http: ws: wss:` is every origin that exists, cleartext included. The app
ships a Luau runtime, a WASM runtime, and plugin-rendered documents; those
sandboxes are well built (see _Verified clean_), and then the webview they render
into can `fetch()` note contents to any host on the internet. The Rust-side
sandbox is doing work the CSP hands straight back. `frame-src` additionally
allows framing any loopback port, not just the preview service's.

**Fix.** `connect-src 'self' ipc: http://ipc.localhost` plus the configured
sync/relay origin, which is already known at runtime from the single
`account.serverUrl` setting.

### H8 — Replay guard is O(n²) over a 5-minute window on the UI thread

- [x] Fixed and tested

`src/lib/sync/signed-collab-frame.ts:196`:

```ts
accept(timestamp, signature, now = Date.now()): boolean {
  …
  const key = bytesToBase64(signature);              // char-by-char string concat
  …
  for (const [seenKey, seenExpiry] of this.seen) {   // full sweep, every frame
    if (seenExpiry <= now) this.seen.delete(seenKey);
  }
```

`REPLAY_WINDOW_MS = 5 * 60_000`, and awareness frames are unthrottled —
`src/lib/sync/collab-provider.ts:168` sends on every `awareness.on('update')`,
which y-prosemirror fires on every selection change (every keystroke and cursor
move). The map holds thousands of entries and each accepted frame iterates all of
them, with the key built by `bin += String.fromCharCode(…)` in a loop.

**Fix.** Sweep on an interval (or only when `size` exceeds a bound) rather than
per frame; throttle awareness sends to animation-frame cadence, as other Yjs
providers do.

**Worth investigating** as a contributor to the T4 WebView paint-deadline flake:
the multiremote WDIO suite is exactly the scenario that saturates this path (two
live clients exchanging awareness), its failure mode is a 30 s paint deadline,
and main-thread O(n²) work driven by cursor movement is a plausible mechanism. It
would also explain why `backend:test:reset` does not help.

## Medium

### M1 — Six hand-rolled autosave state machines

- [x] Fixed and tested

`scheduleSave` is defined six times. `SAVE_DEBOUNCE_MS = 800` lives in four
places (`src/lib/ink/editor-helpers.ts:11`, `src/lib/pdf/viewer-helpers.ts:60`,
and hardcoded again in `FreeformNoteEditor` and `KanbanNoteEditor`). The suspend
flush has six different guards:

| Editor         | Guard                                      |
| -------------- | ------------------------------------------ |
| InkWeb         | none                                       |
| PluginDocument | none                                       |
| Freeform       | `saveTimer`                                |
| Pdf            | `saveTimer`                                |
| NoteEditor     | `!saveTimer → return`, separate persist fn |
| Kanban         | `saveTimer && saveReady && !isTrashed`     |

Only Kanban refuses to flush a write to a trashed note, though Freeform and Pdf
both guard `scheduleSave` on `isTrashed` — so they consider it a bug, they just
do not check it where a note trashed mid-debounce still has an armed timer.

`src/lib/editor/suspend-flush.ts` asserts "Every editor debounces its save
(800 ms)" in prose. Nothing enforces it.

**Fix.** `createSaveScheduler()` in `$lib/editor/`, built on the existing
`suspend-flush.ts` seam. One constant, one trash guard, one flush contract. Fold
H1's token guard into the same helper.

### M2 — The coverage gate cannot fail

- [x] Fixed and tested

`vitest.config.ts` carries a 60-line exclude list removing all 145 `.svelte`
files plus editor/collab/PDF glue, each entry justified as "covered by e2e".
Meanwhile `codecov.yml` sets `informational: true` on both project and patch, and
the CI coverage job is `continue-on-error`. Carved denominator, unfailable gate.
Only 6 of 126 components have unit tests; none of the 8 largest.

### M3 — WDIO suites are absent from CI

- [x] Fixed and tested

`.github/workflows/test.yml:237` runs only the Playwright browser suite against
`src/lib/api/mock-store.ts` (~57 mock handlers standing in for 136 real Tauri
commands). The WDIO suites — real Tauri, `e2e-tests/app/specs/sharing.e2e.ts` at
721 lines, plus multiremote CRDT convergence — run only locally, manually, and
are known-flaky. This is the promise M2's exclusions are cashing a cheque
against.

### M4 — Duplicated helpers across modules

- [x] Fixed and tested

`base64ToBytes` ×6 (two exported, one buried at
`src/lib/components/FreeformNoteEditor.svelte:636`), `ancestorIsTrash` ×4
byte-identical, `assertRequiredString` ×5, `isRecord` ×4, `setupCollabProvider`

### M5 — Components that are secretly subsystems

- [x] Fixed and tested

`InkWebNoteEditor.svelte` is 3,262 lines containing a canvas renderer, a
viewport/zoom engine, a pointer/touch state machine, a selection tool with its
own clipboard, an autosave scheduler, a collab provider, and a toolbar.
`PdfNoteViewer.svelte` is 2,948 lines with 21 `$effect`s.

### M6 — `packages/svelte-kanban` is vendored with zero tests

- [x] Fixed and tested

3,906 lines, 29 `as any`, no tests, outside coverage, owns a whole note kind. The
least-reviewed code in the repository.

### M7 — `loadTree` is a full-vault read from 33 call sites

- [x] Fixed and tested

`listNotes(true)` returns every note **including trashed**, plus `load_all_tags`,
on every rename, move, create, and PDF import. Combined with H5, each is also two
IPC round trips.

### M8 — Backup merge drops `tags_state`

- [x] Fixed and tested

`backup/merge.rs:216` copies the plain `note_tags` rows across, and the note
INSERT carries `yrs_state` and `payload_schema` but leaves the tags CRDT blob
empty. Merged notes push with tags and a null CRDT state. Lower confidence than
the rest — worth a test more than a rewrite.

### M9 — History capture is not atomic

- [x] Fixed and tested

`insert_prepared` and `enforce_cap` (`src-tauri/src/history/mod.rs:430`) are
separate statements on a bare `&Connection`. A failure between them leaves the
note over its version cap.

## Low

- [x] **L1** — `src-tauri/src/collections/mod.rs:74` guards a `format!`ed table
      name with `debug_assert!`, which compiles out in release. A two-variant
      enum makes the compiler enforce what the assert only documents.
- [x] **L2** — `src-tauri/src/plugins/luau.rs:321` extends the script deadline by
      the elapsed native-tool time, so repeated calls to a slow binary extend the
      500 ms wall clock without bound. Requires the `native_tools` permission,
      which already grants arbitrary process execution, so no real escalation —
      but the timeout control is defeatable.
- [x] **L3** — `search/mod.rs` does `summary.tags = tags.clone()` then reuses
      `tags` for the join; reorder and drop the clone from the hot loop.
- **L4, reviewed dependency retained** — React 19 + react-dom are runtime deps of a Svelte 5 app (for
  Excalidraw), alongside mermaid, pdf.js, pdf-lib, image-js, 8 Milkdown
  packages and 6 CodeMirror packages. 43 runtime deps, 63 Rust crates.
- [x] **L5** — 17% of non-test source is comments, mostly excellent. The
      recurring anti-pattern is a well-argued paragraph explaining why a
      compromise is acceptable where the paragraph cost more than the fix
      (`purge`'s "harmless", search's N+1, `debug_assert`'s "constant at the call
      site").
- [x] **L6** — `src-tauri/scripts/lint-i18n.mjs` checks key parity only. It
      cannot detect an untranslated value or a broken placeholder. The bundles are
      currently clean: 35 of 1,068 strings identical between en and de, all
      legitimately so (product name, `"{count}/{total}"`, `"Wikilinks [[...]]"`),
      and zero placeholder mismatches. No debt today; the gate would not catch the
      regression.
- [x] **L7** — `rewrite_ws_handshake` forwards all non-Host/Origin client headers
      verbatim, and `is_websocket_upgrade` is a substring test with no
      `Sec-WebSocket-Key` / `Sec-WebSocket-Version` validation.
- [x] **L8** — `CollabReplayGuard` uses `Math.abs(now - timestamp) > windowMs`,
      accepting frames dated up to 5 minutes in the future. A skewed or hostile
      sender gets a wider replay window than intended;
      `now - timestamp > windowMs || timestamp > now + skewAllowance` is tighter.

## Verified clean

Checked specifically, nothing found:

- **WASM runtime** (`plugins/wasm.rs`) — wasmi with fuel metering (100M), 128 MB
  memory cap via `StoreLimits`, 5 s wall clock, no WASI linked, fresh `Store` per
  invocation.
- **Luau runtime** — memory cap, interrupt-driven deadline on back-edges,
  `sandbox(true)`, permission-gated `ms.*` namespaces.
- **Package signing** — Ed25519 over a canonical digest of every file, not just
  the manifest, with `signature.json` correctly excluded from its own digest.
- **Secrets** — session key in the OS keychain via `keyring_core`, per-profile
  account names. Every `log::*` / `eprintln!` call site checked for
  token/key/password/session leakage: none.
- **Updater** — minisign pubkey pinned, HTTPS endpoint.
- **Path traversal** — reject `..`, canonicalize, `starts_with(base)`, with a
  negative test (`plugins/discovery.rs:104`).
- **Migrations** — `PRAGMA user_version`, append-only, "never edit a shipped
  migration" honoured across 40 statements.

## The cross-cutting pattern

Every Critical and High finding sits on a **boundary between two well-built
components**. None is inside one.

| Finding | The two halves                         |
| ------- | -------------------------------------- |
| C1      | sharing model ↔ mutation layer         |
| C2      | CRDT merge ↔ dirty-flag protocol       |
| C3      | `trashed_at` column ↔ `TRASH_ID` tree  |
| C4      | insert pass ↔ re-parent pass           |
| C5      | Rust sandbox ↔ local HTTP transport    |
| H5/H6   | two IPC reads ↔ one composed view      |
| H7      | plugin sandbox ↔ webview CSP           |
| H8      | signing correctness ↔ frame throughput |

Subsystems are built to a high standard; the seams between them go unspecified.
That is also why duplication matters more here than it usually would — each copy
of `setupCollabProvider` or `scheduleSave` is another seam, and each fossilises
the version of the design from the day it was pasted.

The process consequence: the gates that would catch drift are all advisory (M2),
the tests covering the risky half do not run automatically (M3), and shortcuts get
documented rather than removed (L5). Enforcement has to come from CI rather than
from remembering.
