# September audit: data fixes

Reviewed against the current `main` baseline on 2026-09-07. This change groups the
database, sharing, sync and backup findings because they share mutation and
transaction boundaries.

| ID  | Disposition                                       | Implementation and regression evidence                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| --- | ------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| C1  | Fixed; part of the original evidence was outdated | Scope sync already rejects read-only pushes, repairs local edits and withholds live collaboration keys. The remaining local mutation gap is closed by `sharing/permissions.rs`. Notes, CRDT saves, assets, collection changes, batch moves and deletes, and backup destinations check ancestor and scope permissions before writing. Tests reject read-only edits and asset uploads, forbid moving a parent containing a read-only share, preserve batch sources, and allow read-write recipients and owners. Existing `purge_local_scope_removes_scoped_rows_and_cursors` and `scopes_to_purge_flags_scopes_absent_from_live_set` cover revoked-scope cleanup. |
| C2  | Fixed                                             | All four push paths use `acknowledge_push`. Receipts clear dirty only when the snapshotted modification timestamp still matches. Concurrent edits retain their dirty flag and tag CRDT while receiving the first remote identity. Scope/identity guards prevent a completed upload from reattaching a moved or deleted row; its old scoped item receives a tombstone. `receipt_tests` cover concurrent edits, a later clean acknowledgement, rehoming and deletion.                                                                                                                                                                                             |
| C3  | Fixed                                             | Migration 25 repairs old direct-trash note parents and defines `active_notes` using recursive folder ancestry. Search, normal note listing and both PDF indexing queries use this view. Direct trash and restore now update the tree parent as well as the timestamp. Tests cover nested trashed folders, restored visibility, direct trash/restore, and a populated version-24 database upgrade.                                                                                                                                                                                                                                                               |
| C4  | Fixed                                             | Backup merge tracks the exact inserted folder IDs in a `HashSet`; only those folders can receive backup parents. `merge_keeps_existing_root_parent_and_preserves_tag_crdt` proves an existing root folder stays at the root.                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| H3  | Fixed                                             | Single-note purge opens a transaction around tombstones and deletion, and reuses an existing batch transaction. Collection deletion follows the same transaction rule. A trigger-induced note delete failure proves the note survives and no tombstone escapes.                                                                                                                                                                                                                                                                                                                                                                                                 |
| H4  | Fixed                                             | Migration 25 creates an FTS5 trigram index with note and tag triggers and backfills existing content. Search loads indexed substring candidates and their tags in one SQL statement. The command releases the database mutex before ranking and snippet work. Tests cover candidate filtering, literals containing quotes, short queries, title/body ranking, tags, PDF text, updates, deletion and migration backfill.                                                                                                                                                                                                                                         |
| M8  | Fixed                                             | Backup merge copies `tags_state` alongside plain tag rows. The backup regression compares the imported CRDT bytes and decoded tags with the source.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| M9  | Fixed                                             | History insertion and cap pruning share one transaction, including the command's prepared off-lock capture path. `capture_rolls_back_insert_when_cap_pruning_fails` forces pruning to fail and verifies the new version is rolled back.                                                                                                                                                                                                                                                                                                                                                                                                                         |
| L1  | Fixed                                             | `TrashTable` replaces the string table argument and debug-only assertion. The compiler restricts the interpolated table names to notes and collections. Direct and batch trash tests exercise both variants.                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| L3  | Fixed                                             | Ranking uses the candidate's existing tag vector directly; the per-note clone is removed. Tag-match and index-trigger regressions cover the result.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| L5  | Fixed for the cited compromises                   | Removed the purge tombstone justification, per-note tag-query rationale and debug-only table-name assertion rationale by fixing the underlying code. Their corresponding regressions are listed above.                                                                                                                                                                                                                                                                                                                                                                                                                                                          |

Search preserves substring behavior for one- and two-character terms with an
active-note fallback because trigrams require three characters. Normal indexed
queries avoid materializing unrelated note bodies. Ranking returns at most 200
hits. Migration 25 builds the index once when an existing database first opens.

Validation results are recorded in the draft PR after the Rust formatting, lint
and full test gates complete. Tests use local SQLite databases and sync receipt
fixtures; they do not require an Etebase account.
